# 以页面案例完善 pyv8c

把案例中的可观察失败转化为可复用的浏览器能力：确定目标，寻找最早因果分歧，建立同条件复现，修复所属层，验证并复测。网站的 HTTP 200、单个 token、trace 变少或某个局部值一致，都不足以证明目标达成。用户的范围、工具偏好和授权优先；保留已有工作区改动，不默认升级 V8、IDL、浏览器档案或提交代码。

## 工作路径

1. **建立条件与基线。** 先检查项目现状、已有样本和目标。记录源码与原生扩展、Python/V8/Chrome、IDL/profile、origin、代理、会话、权限和实际操作。优先复用现有 HAR、脚本和离线样本；它们足够时不为凑流程启动浏览器。需要真实访问时先确认用户已授权相应工具和操作。工具不可用时记录限制，继续可独立完成的工作。
2. **从目标倒查最早分歧。** 先观察无注入的加载及操作结果，再按需要增加脚本过滤 trace、断点或局部探针。比较同一脚本、Realm、操作和前置状态下的返回值、异常、身份、任务与后续效果。区分未观测、undefined、被捕获异常、资源失败和实际缺陷；网络状态或单个异常只是候选证据。
3. **必要时追踪真实数据链。** 对加密遥测或混淆代码，从请求参数反查序列化及加密前输入、实际读取位置、分支与消费者。使用成功/失败样本时核对来源、脚本版本、会话及有效期；稳定条件下单变量验证，不把动态值、排序或单次服务端结果直接归因于框架。具体方法见 [数据链与样本对照](references/payload-parity.md)。
4. **落到浏览器语义。** 提取同字节、origin、响应和操作顺序的最小场景，对照 Chrome。检查对象和描述符、跨 Realm 身份、状态持久性、事件/微任务和生命周期，而非只比较字符串。按原生绑定、执行器、资源或 Web API 的职责修复；不伪造成功值、删除检测或复用真实浏览器认证状态。
5. **验证并继续。** 运行针对性回归和必要的架构/集成测试；涉及异步、导航或关闭时覆盖取消和迟到结果，竞态按风险重复。需要时在相同条件下复测原站；仍未达到目标则继续查下一处分歧。外部会话、工具或服务阻塞时保留证据并完成独立可做的工作，不将外部成功作为唯一验收依据。

## 证据与结果

每条结论标明：**候选差异 → 已定位读取/分支 → 同条件 Chrome 和本地复现确认 → 修复与回归 → 原站结果**；不适用的阶段明确写未完成。记录采集来源、完整性、观察者影响和原始证据位置；未捕获不等于未发生。固定时间/随机输入只用于控制实验，真实会话与跨 Realm 状态不得无证据混用。账号、Cookie、令牌和明文遥测保存在用户授权的私有位置，报告或提交前脱敏。

优先使用框架已有能力，包括 `trace_scripts`、本地资源加载、网络拦截和执行器；工具只在其实际覆盖范围内提供证据。Chrome 必须使用明确的本机可执行文件或用户指定方式；是否允许 MCP、自动化、站点写操作以及交付形式遵循用户要求，不擅自扩大。完整采集链、trace 边界与验收见 [证据与 trace](references/trace-parity.md)。
