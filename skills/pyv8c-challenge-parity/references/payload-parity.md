# 遥测数据链与样本对照

当页面把多个环境检查编码、压缩、加密后发送，优先定位实际执行的数据链：

```text
当前脚本与会话 → 环境读取/异常 → 中间结构 → 序列化字节
→ 压缩/加密 → 请求体或头 → 响应 → 页面后续状态
```

从实际请求发送点向前追踪参数生产和调用栈；先确认观察的是本次页面实际调用，而非同名无关函数、解码常量或未触发的分支。可在授权范围内使用源码、source map、AST、断点、局部插桩或 trace；记录脚本 URL、摘要、源码位置、Realm 与时序。只读取分析需要的样本，不因猜测增加无关请求或重放有副作用的操作。

## 采集与观察者效应

先保存无注入结果，再进行最小观测并比较页面状态、请求和响应。Hook/代理、全局新增属性、函数包装、枚举、暂停和输出本身可能改变检测；出现分支或结果变化就把该样本标为受干扰，重新选择观测方法。禁止把 Hook 没命中解释为对应代码未运行，也不要依赖隐藏变量或魔法常量让探针伪装成真实浏览器。

对每份数据记录采集点是在加密前的对象、编码后字节还是网络实体；保留原始类型、顺序、空洞、undefined/null、长度、编码与异常。明确是否有截断、缓冲区溢出、未完成响应或不确定请求归因。敏感明文、Cookie、令牌只放用户授权的私有位置，分享与版本控制前脱敏；不要把脱敏数据当可直接重放的原始样本。

## 成功与失败样本

对每个样本记录成功判据、原始来源、时间、脚本/二进制摘要、origin、网络出口、浏览器版本、会话与采集方式。先确认业务响应确实成功，区分关联但不属于同一轮的请求、刷新后的 token、缓存和不同脚本版本。若不可比，只保留假设，不做字段级因果结论。

用多组样本区分稳定字段与时间、随机、设备、权限和会话相关字段；比较对象关系与条件，而不是只比较字符串或数组中 null 的数量。对于候选差异，定位具体生产表达式、读取值、转换及消费者分支；在本地 fixture 中固定其他条件，逐项改变一个变量，观察是否能复现与消除分歧。记录负对照、反例和仍未受控的条件。仅在授权且必要时做有界原站复测；服务端响应受网络、限流和其他输入影响，单次成功不能证明唯一根因。

## 成为框架修复之前

先确认差异是同条件下的浏览器语义，而不是用户配置、操作差异、当前服务端状态或采集污染。将检测方法提炼为本地 JS 测试，覆盖返回类型、异常、属性描述符、对象身份及状态变化；Chrome 对照与 pyv8c 使用相同 origin、脚本和操作。按框架分层修复并加入回归，复测原始数据链后分别报告页面结果与框架验证结果。
