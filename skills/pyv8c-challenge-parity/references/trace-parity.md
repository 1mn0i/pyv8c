# 证据、trace 和验收

## 区分事实与解释

原始日志保存发生的事件；候选差异表示值得调查；确认缺陷要求相同前提下的 Chrome 对照及可重复复现。不能把这三个层次合成一个“差异计数”。

trace 不记录全部 JS 逻辑，也不保证捕获全部资源/任务。`undefined` 可能是正常返回、权限或上下文限制；异常可能是页面故意捕获的 feature detection；少一个请求可能来自更早的分支、缓存或取消。按方法名字维护“void 白名单”会掩盖真实差异，不这样过滤。

```powershell
python skills/pyv8c-challenge-parity/scripts/trace_analyze.py evidence/run/events.jsonl --out evidence/trace-candidates.json
```

支持文本 trace 与运行器 JSONL。聚合保留 Realm、访问类型、名称、信号及原始行号/样例；不识别的结构化 trace 保留为 unclassified，不能算没有访问。真实 trace 格式变化时先检查原始样例再修解析器。

Chrome 侧依赖 DevTools/CDP/事件与同源局部探针，不存在与原生 trace 一一对应的同格式日志。用共同的因果事实对齐：某脚本、某操作、某个 Realm 的返回值/异常和后续效果。只比较总调用数通常没有意义。

## 证据条目

一条结论至少包含：

- 前置条件与目标：页面、操作、origin、Realm、阶段和版本。
- 两侧事实：请求/响应/返回类型/异常/事件，原始文件与位置；未采集项明确标为未观测。
- 因果链：哪个差异使哪个消费者走到不同分支，怎样阻断目标。
- 分类和置信度：已确认缺陷/功能缺失/配置版本/服务端/观察者/待验证。
- 最小复现、修复层与测试；新证据推翻旧结论时明确撤回。

默认工具记录源码 HEAD、状态、tracked diff 摘要和运行二进制/IDL/profile 摘要；未跟踪文件内容需在正式案例中另外保存摘要。Chrome 启动参数、实际 UA、视口可在结果中查看。`pyv8_version` 是包版本；原生 V8 版本另存于 `v8_version`。Chrome 构建和 JS 引擎版本通过 CDP 记录；命令行优先 CDP，受限时用可选 psutil 读取本次拥有的子进程，均不可用时明确标记 unavailable 和原因，不修改启动参数来采集元数据。

## 验收次序

1. 本地失败复现被修正，两侧具体语义一致；确认 fixture 没有因宽泛应答而掩盖错误。
2. 受影响 API、加载顺序、跨 Realm、安全规则及失败路径回归通过。
3. 资源和生命周期改动覆盖导航/移除/终止/关闭/迟到回调；竞态至少五轮。
4. 核心桥接、调度或资源管线改动运行相关仓库全量、慢速及架构/策略检查；Chrome 相关套件串行运行。
5. 原站无注入复测目标并保存阶段推进；缺少外部条件时报告阻塞，不能通过扩大超时无限重试。

既有失败逐项对照；不能放宽断言、增加排除或改基线使新失败消失。性能改动才增加同条件多轮测量；本 skill 的普通正确性修复不宣称提速。

## 已有证据的演练方法

选择一个已有的 frame 文档/资源或跨 Realm 案例，只读取原始事实而非照抄结论。按“目标 → 阶段 → 最早分歧 → 局部表达式 → 本地回归”重新建立链条，再与已有修复比较。不能把历史案例中某条猜测升级成新 skill 的通用规则。
